## 结论与适用范围

用户提供的截图、请求记录及后补 Server 日志支持：在本次 iPhone、固件和鼠标设置下，
分轴校准配合 `HIDAGENT_AXIS_MOVE=1`（按下前先 X 后 Y）明显改善了原来的位置偏差。
所测横向、纵向和跨轴目标接近预期；重复目标视觉一致。不是像素级测量，不能推广到
其他设备、方向、鼠标设置、屏幕边缘、快速连续调用或拖动精度。

这支持“校准与执行的移动路径响应不同参与了误差”的假设，但不能证明具体机制一定是
iOS 鼠标加速。没有按截图估值增加固定补偿，也没有修改固件步长或节奏。

## 代码边界与操作要求

- 自动视觉校准失败统一重新归位再移动 200/200，修正部分成功后仍使用错误手动距离的问题。
- 手动完成清空旧 seen；四步分轴校准全部有效后才保存，取消不覆盖旧参数。
- 分轴采样只覆盖固定 150/350 单位；撞边需取消，不保证适合所有设备。
- 移动失败使位置未知，不能继续点击，下一次定位重新归位。
- 校准写入使用同目录临时文件替换，避免直接截断旧文件；这不是断电持久性保证。
- 先 X 后 Y 只用于按下前定位；按下后的拖动、视觉 aim 修正、归位和保活沿用原行为。
- 单个 HID 命令串行不等于整个手势串行；测试和校准必须暂停其他控制来源，不支持并发操作者。
- 关闭/返回网页不会取消后端校准；使用取消校准或 stop。设备断开时 stop 也应清理采样状态。
- INFO 日志包含坐标和移动元数据，应限制访问；未增加输入文字日志。
